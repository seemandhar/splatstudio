# Contributing

New methods can live in external repositories. Use `ss-create`, register a `splatstudio.methods` entry point, and follow the [authoring guide](docs/custom-methods.md). Contributions to the shared runtime should include a small reproducer for the behavior being changed and appropriate numerical or integration checks.

```bash
pip install -e '.[runtime,data,dev]'
pytest -q
ruff check src tests examples scripts
python scripts/check_repository.py
```

CPU CI checks contracts, data handling, gradients, state transitions, paired reporting, packaging, and documentation consistency. CUDA reports are published separately; GitHub-hosted CPU CI does not imply GPU validation.

For a new catalog entry, provide source provenance and a license, paper links where applicable, installation and data requirements, the actual test scope, known approximations, and failure cases. Preserve original method attribution. Do not label an import or a short training run as a faithful reproduction.

For results, record data/split/metric conventions, source hashes, seed, training recipe, resource use, per-scene and per-view metrics, and all failures. Use validation data for selection and freeze the recipe before evaluating held-out test views. Comparisons should show absolute and worst-case errors; any average should identify its aggregation rule. Keep historical exports separate from rerun results.

Documentation images are generated by `scripts/render_brand.py` and `scripts/publish_results.py` (`pip install -e '.[reports]'` supplies plotting dependencies). The method index/cards are generated by `scripts/build_catalog.py` from `src/splatstudio/catalog.json`. Please regenerate those artifacts when changing their inputs.
